# 由 Host 插件把上游 MCP 工具代理为 dsh 原生工具

agent 使用的记忆工具没有走 dsh 自带的 MCP 客户端直连上游，而是由 Host 插件从上游 MCP 动态读取工具列表，转成 dsh 原生工具，再按白名单暴露给 agent。原因是 dsh 的 `tools/pre-execute` 只能放行、拒绝或询问，不能改写工具参数。而生效知识库的约束需要在调用时处理 `project` 参数：只有一个生效知识库时自动补上，有多个时要求 agent 显式指定，超出生效范围就拒绝。代理层把这些规则集中在一处，上游新增的工具也会随工具列表自动同步过来。

## Considered Options

- **dsh MCP 客户端直连上游，用 `tools.restrict` 隐藏工具、用 guard 拒绝越界调用**：实现简单，但无法补全默认知识库，agent 每次调用都必须自己写对知识库名，默认值只能靠提示词约束。
- **Host 插件做通用代理**（采纳）：多了一层转发，但生效知识库的计算、默认值和越界拦截都由代理层统一负责。
